AI Agent Team Brief

Full Stack Exam Management System - Milestone 1

Use this document as the main instruction file for the Team Leader agent and the implementation agents.

1. Executive Decision
Yes, the project should start now. Milestone 1 should not attempt to finish the full production system. It should establish a clean, modular foundation and implement a convincing client-side MVP with mocked persistence, role-based flows, documentation, Git history, and diagrams.
Main objective for Milestone 1: deliver a structured React application foundation for an online exam management system, with clear Teacher and Student workflows, generic services, mock data, diagrams, and meaningful Git commits on the dev branch.

2. Full Project Context
The final course project is a Full Stack web application for managing online exams and student submissions. The system must eventually include frontend, backend API, database integration, authentication and authorization, persistent storage, and deployment.
User Type
Main Responsibilities
Expected Capabilities
Teacher / Lecturer
Manage the exam lifecycle
Create exams, edit exams, add questions, manage question types, publish exams, review submissions, grade exams, publish results.
Student
Take exams and view results
Login/register, view available exams, enter an exam, submit answers, view grades and feedback.
Admin / Future Optional Role
Manage users and system settings
Manage teachers/students, view system statistics, configure global settings. This is optional for Milestone 1.

3. What Milestone 1 Means
Milestone 1 is a planning and foundation milestone. It should prove that the team understands architecture, modular work, Git workflow, services, page structure, mock persistence, and documentation. It does not need to include a complete database, deployment, or all advanced features yet.

3.1 Required Outputs for Milestone 1

GitHub repository with work committed to the dev branch, not directly to main.

Modular client application structure, preferably React with Vite.

Authentication pages: Login and Register.

Teacher pages: dashboard, exam list, create exam, edit exam, submissions/review placeholder.

Student pages: dashboard, available exams, exam-taking page, grades/feedback page.

Navigation menu that changes according to the logged-in user role.

Generic services implemented using OOP where appropriate: ConfigService, StorageService, LoggerService, NotifyService, MockApiService, AuthService, ExamService, SubmissionService.

Mock DB / mock API layer with persistent localStorage-based data.

Plain text documentation file, not only Markdown, describing features, use cases, users, pages, services, and current limitations.

Diagrams: Component Hierarchy, UML/Class Diagram for services and entities, Main DB/View Entities, and optionally Use Case Diagram.

Gemini CLI /init performed and documented if the course requires it.

Commit history that shows modular progress, including separate commits for comments/documentation if required by the lecturer.

3.2 What Not To Do in Milestone 1

Do not spend time building microservices, sockets, AI agents, analytics, CI/CD, or advanced monitoring yet.

Do not over-engineer PostgreSQL/JWT/deployment before the client flow and architecture are clear.

Do not place all logic inside React components. Business logic should go into services.

Do not make one giant commit. Every feature/module should have its own commit.

Do not work directly on main. Keep main stable and do Milestone 1 work on dev.

4. Research Findings and Technical Direction
The short research phase supports a simple but professional architecture for this milestone: feature/route-based React organization, separated Express backend structure for later stages, GitHub-style collaboration through branches and pull requests, and text-based UML diagrams using PlantUML or Mermaid.
Topic
Research Finding
Decision for This Project
React structure
React documentation supports grouping files by feature or route for maintainability.
Use a feature/page-based client structure: auth, teacher, student, shared/components, services, config, routes.
Backend structure
Express is routing/middleware-oriented and works well with routes, controllers, services, models, and middleware.
Create a server skeleton now, but keep backend implementation minimal or mocked in Milestone 1.
Git workflow
GitHub collaboration is based on branches and pull requests; main should remain stable.
Use dev as the working branch. Optionally create feature branches from dev and merge back into dev.
Diagrams
PlantUML supports use case and class diagrams using plain text.
Store diagram source files as .puml or .txt inside docs/diagrams, so AI agents can edit them easily.
Milestone scope
Advanced features improve creativity but can distract from the required foundation.
Focus on a polished MVP foundation: role-based pages, mock flows, services, documentation, diagrams, commits.

5. Recommended Milestone 1 Feature Set
The following feature set is the recommended scope. It is strong enough to look professional, but limited enough to finish cleanly.

5.1 Must-Have Features

Login and Register using mock authentication.

Role-based user model with at least two roles: teacher and student.

Navigation menu that displays different links for teacher/student.

Teacher can create an exam with title, description, duration, status, and questions.

Teacher can edit an existing exam.

Teacher can change exam status: Draft, Published, Closed.

Student can view published exams only.

Student can open an exam and submit answers.

Student can view submitted grade/feedback if available.

Mock database stored in localStorage so data remains after refresh.

Clear service layer that hides storage/mock API logic from components.

Documentation and diagrams prepared from the beginning.

5.2 Nice-to-Have Features if Time Allows

Auto-save draft answers while the student is taking an exam.

Basic notification system for success/error messages.

Basic validation: required fields, invalid email, empty exam title, empty question text.

Simple dashboard counters: number of exams, published exams, submissions, completed exams.

Basic responsive layout for desktop and mobile.

Initial backend Express skeleton with health endpoint and route placeholders.

5.3 Features to Save for Later Milestones

Real JWT authentication with password hashing.

PostgreSQL schema and real database integration.

Real grading workflow with teacher feedback editor.

Real-time monitoring with sockets.

AI-based grading or question generation.

CI/CD pipeline and cloud deployment.

Advanced analytics dashboard.

Microservices.

10. Recommended Git Workflow

Create repository on GitHub.

Create and push dev branch.

All implementation commits go to dev, not main.

Optional: create feature branches from dev, for example feature/services, feature/auth, feature/teacher-pages.

Each module/feature gets a separate commit.

Documentation/comments can be committed separately if required by the lecturer.

Open a pull request from dev to main only when the milestone is stable and reviewed.

git checkout -b dev
git push -u origin dev

git checkout -b feature/services
git add .
git commit -m "feat: add generic client services"
git checkout dev
git merge feature/services
git push origin dev
