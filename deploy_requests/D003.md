### What to build

#### 1. Entity models (`client/src/models/`)

Per spec §7. Plain JS classes (or factory functions) with:
- A constructor that takes a plain object and validates required fields.
- Required-field validation throws `Error` with a clear message.
- A `toJSON()` method for serialization.
- A static `fromJSON(obj)` for hydration from StorageService.

Fields per spec §7:

- **User** — `id, name, email, password, role` (`role` ∈ {teacher, student}).
- **Exam** — `id, title, description, durationMinutes, status, createdBy, questions, createdAt`. `status` ∈ Config.getExamStatusOptions(). `questions` is an array of Question instances OR plain objects (decide and document).
- **Question** — `id, examId, type, text, options, correctAnswer, points`. `type` ∈ Config.getQuestionTypes(). `options` is `[]` for `open-text`, non-empty array for `multiple-choice`. `correctAnswer` semantics per type (index/string for MC, optional for open-text).
- **Submission** — `id, examId, studentId, answers, status, grade, feedback, submittedAt`. `answers` is an array of Answer instances or plain objects.
- **Answer** — `questionId, value`. Embedded in Submission (not stored separately).

ID generation: use `crypto.randomUUID()` (browser-native; Vite supports it). Wrap in a small `models/util.js` if you want.

#### 2. seedData (`client/src/data/seedData.js`)

Export a function `getSeedData()` returning a plain object:

```js
{
  users: [<one teacher, one student — both with password "password" for M1 mock>],
  exams: [<at least one Published exam with 2+ questions, one Draft exam>],
  submissions: [<empty array OR one demo submission>]
}
```

IDs hard-coded (UUIDs string-literal) so seed is deterministic and easy to reason about. Document the demo creds in `docs/ai-work-log.txt`.

#### 3. MockApiService (`client/src/services/MockApiService.js`)

Per spec §8. CRUD over the mock localStorage-backed "DB". Uses StorageService + Config.

```js
class MockApiService {
  constructor(storage, config, logger) { ... }
  async seedIfEmpty()                         // if storage is empty, write seed data
  async get(collection)                       // returns array of records
  async getById(collection, id)               // returns record or null
  async post(collection, record)              // appends, returns persisted record (with id if missing)
  async put(collection, id, record)           // replaces, returns updated
  async delete(collection, id)                // removes
  async clear(collection)                     // wipes one collection
}
```

`collection` ∈ {`users`, `exams`, `submissions`}. Map collection → storage key via Config.getStorageKeys().

All methods async (return Promises) even though localStorage is sync — this future-proofs the interface for real-backend swap in M2.

#### 4. App boot wiring

Update `client/src/app/App.jsx` to:
- Import MockApiService (via a shared singleton: `client/src/services/index.js` exporting wired instances of all services seen so far).
- Call `mockApi.seedIfEmpty()` on app mount (use `useEffect` with empty deps).
- The landing page text now reads "EMS_M1 — mock data seeded".

`client/src/services/index.js` is the dependency-injection root: it wires services into each other (e.g., MockApi receives Storage, Config, Logger instances) and exports a singleton bundle:

```js
export const config = new ConfigService();
export const logger = new LoggerService();
export const storage = new StorageService(logger, config);
export const notify = new NotifyService();
export const mockApi = new MockApiService(storage, config, logger);
```
