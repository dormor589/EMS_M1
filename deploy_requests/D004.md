### What to build

#### 1. AuthService (`client/src/services/AuthService.js`)

Per spec §8:

```js
class AuthService {
  constructor(mockApi, storage, config, logger) { ... }
  async login(email, password)      // returns User on success, throws on invalid creds
  async register({ name, email, password, role })  // creates user, returns User
  logout()                          // clears current user from storage
  getCurrentUser()                  // returns User or null
  isAuthenticated()                 // bool
  isTeacher()                       // bool
  isStudent()                       // bool
}
```

- On `login`: look up user by email in MockApi `users` collection; compare password (plain text — M1 mock; document the limitation in code comment + work-log); on match, persist current user via StorageService under `ems_current_user` key; throw `Error('Invalid credentials')` on fail.
- On `register`: validate required fields; reject duplicate email (`Error('Email already registered')`); default `id = crypto.randomUUID()`; insert via MockApi.post; auto-login (set current user).
- `logout` removes the storage key.
- `getCurrentUser` reads from storage and rehydrates a `User` model.
- `isTeacher`/`isStudent` check role.

#### 2. LoginPage (`client/src/pages/auth/LoginPage.jsx`)

- Controlled form: email + password.
- On submit: call `auth.login(...)`; on success, redirect (use `useNavigate` from react-router-dom) to `/` (landing is fine; full role-aware routing comes in D005); on error, render the error string above the form (use NotifyService to also `error()`).
- Link to `/register`.
- Demo creds hint visible in dev (e.g., "Demo teacher: teacher@ems.dev / password" — read from a small constant or hard-code, since these are the seed user creds).

#### 3. RegisterPage (`client/src/pages/auth/RegisterPage.jsx`)

- Controlled form: name, email, password, role select (teacher/student).
- Validation: all fields required; email matches a basic regex; password >= 4 chars (M1 — document limitation).
- On submit: `auth.register(...)`; on success: redirect to `/`; on error: render + NotifyService.error.
- Link to `/login`.

#### 4. Routing scaffold

Even though D005 owns the full routing, D004 needs a minimal router so Login/Register pages are reachable:

- `client/src/app/routes.jsx`: define routes `/`, `/login`, `/register`.
- `client/src/app/App.jsx`: wrap in `<BrowserRouter>`; show NavLinks "Login | Register" if unauthenticated, "Logout" if authenticated, and the current user's name + role inline.
- A bare `LandingPage` component (inline in App.jsx is OK) shows: "Welcome <name> (<role>)" when authenticated, "Please log in or register" when not.

D005 will replace this with the real MainLayout + role-based NavigationMenu + route guards.
