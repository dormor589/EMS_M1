### What to build

Implement four OOP service classes as ES modules. Each is a JavaScript **class** with clearly-scoped methods. Singletons are exported as instances OR via a `getInstance()` static; pick one convention and apply consistently across all four.

#### 1. ConfigService (`client/src/services/ConfigService.js`)

Central configuration. Per spec §8:

```js
class ConfigService {
  getApiMode()           // returns "mock" (in M1)
  getStorageKeys()       // returns object: { users: 'ems_users', exams: 'ems_exams', submissions: 'ems_submissions', currentUser: 'ems_current_user' }
  getDefaultExamStatus() // returns "Draft"
  getExamStatusOptions() // returns ["Draft","Published","Closed"]
  getRoles()             // returns ["teacher","student"]
  getQuestionTypes()     // returns ["multiple-choice","open-text"]
}
```

All values are constants defined at module top (this is the project's `constants.py` equivalent — see overlay).

#### 2. LoggerService (`client/src/services/LoggerService.js`)

Per spec §8: `info()`, `warn()`, `error()`. Wraps `console.*` internally — this is the **only** file in the codebase allowed to call `console.*` directly. All other files use LoggerService.

```js
class LoggerService {
  info(msg, ...args)
  warn(msg, ...args)
  error(msg, ...args)
  // optional: setLevel('debug'|'info'|'warn'|'error')
}
```

Include a level filter: messages below the current level are dropped. Default level = `info`.

#### 3. StorageService (`client/src/services/StorageService.js`)

Per spec §8: wrapper around `localStorage`. Methods `get(key)`, `set(key, value)`, `remove(key)`, `clear()`. Serialize values as JSON; deserialize on get; return `null` if missing or parse fails (and log via LoggerService).

**This is the ONLY file allowed to touch `localStorage`** (overlay anti-pattern #2). All other code uses StorageService.

```js
class StorageService {
  get(key)            // returns parsed value or null
  set(key, value)     // JSON.stringify + setItem
  remove(key)
  clear()             // clears only ems_* keys, not unrelated app state
  has(key)            // bool
}
```

`clear()` MUST be scoped: only remove keys prefixed `ems_` (so we don't wipe unrelated app/browser state).

#### 4. NotifyService (`client/src/services/NotifyService.js`)

Per spec §8: success / error / warning notifications. M1 implementation can be minimal — internally use an in-memory listener pattern:

```js
class NotifyService {
  success(msg)
  error(msg)
  warning(msg)
  subscribe(listener)  // returns unsubscribe fn
}
```

A subscriber is a callback `(notification) => void` where notification is `{ type: 'success'|'error'|'warning', message: string, id: string, timestamp: number }`. Pages can subscribe later to show toasts; M1 doesn't need a visible UI for notifications, but the wiring must work.

#### Tests

`client/src/services/__tests__/`:
- `ConfigService.test.js` — verify each getter returns expected constants; types/shape match.
- `LoggerService.test.js` — info/warn/error fire; level filter drops below-threshold logs. Mock console.
- `StorageService.test.js` — round-trip (set then get); remove deletes; clear only removes `ems_*`; null on missing key; null on malformed JSON.
- `NotifyService.test.js` — subscribe receives emitted notifications; unsubscribe stops; success/error/warning all dispatch with correct type.

≥3 tests per service. Total ≥12 tests.
