## D009 — Manual QA walkthrough + polish + user-gated dev → main PR

**Date:** 2026-05-24
**Status:** active
**Tier:** 3
**Risk class:** CRITICAL (final acceptance gate)
**Depends on:** D008
**Estimated time:** ~1h
**User gate:** YES — HALT for explicit user approval before opening PR.

### Spec source

`docs/spec_brief.txt` §12 (12 acceptance criteria) + §16 (13-step Manual QA Checklist).

### Affected zones

- Possibly: any file that fails QA. Polish fixes only.
- New: `docs/manual_qa_checklist.txt` with the §16 checklist annotated PASS/FAIL.
- Modified: `docs/explanation.txt` if it needs updates after polish.
- Modified: `docs/ai-work-log.txt` (final D009 entry).

### What to build

#### 1. Run the §16 Manual QA Checklist end-to-end

Boot `cd client && npm install && npm run dev` in one terminal. Open browser. Execute each of the 13 §16 steps in order. Record actual observed behavior:

```
1. App opens locally without errors — PASS/FAIL + note
2. Register a teacher user — PASS/FAIL + note
3. Login as teacher — PASS/FAIL + note
4. Create new exam with >=2 questions — PASS/FAIL + note
5. Publish the exam — PASS/FAIL + note
6. Logout — PASS/FAIL + note
7. Register or login as student — PASS/FAIL + note
8. Published exam appears in Available Exams — PASS/FAIL + note
9. Open exam and submit answers — PASS/FAIL + note
10. Refresh — submission still saved — PASS/FAIL + note
11. Teacher can see the submission — PASS/FAIL + note
12. Navigation differs Teacher vs Student — PASS/FAIL + note
13. docs/ and docs/diagrams/ committed on dev — PASS/FAIL + note
```

Write the annotated checklist to `docs/manual_qa_checklist.txt`.

#### 2. Verify the §12 12 acceptance criteria

Cross-check each criterion against the live app. If any fail, fix them (minimal polish — don't expand scope). Document the fixes in commits with clear messages.

#### 3. Polish

- Verify `npm run build` succeeds with no warnings (or document remaining warnings).
- Verify `npx vitest run` passes 100%.
- Run `npm run lint` if ESLint is configured; fix or document.
- Visual polish: no obvious broken styling, all pages reachable, links work.
- README accurately describes install + run.

#### 4. Final ai-work-log entry

Append:
```
D009 — <timestamp>
  Manual QA checklist 13/13 PASS (see docs/manual_qa_checklist.txt).
  Spec section 12 acceptance criteria: 12/12 PASS.
  Polish: <fixes if any>.
  Final test count: <N> tests passing.
  Wall time: <minutes>.
  Milestone 1 ready for dev -> main PR (awaiting user approval).
```

### Required commit structure

1. (If polish fixes needed) one `fix: ...` commit per fix.
2. `docs: add manual QA checklist results (13/13 PASS)`
3. `docs: append D009 entry to ai-work-log`

After last commit: `git push origin dev`.

### Acceptance criteria

- [ ] All 13 §16 Manual QA Checklist items PASS in a live browser session.
- [ ] All 12 §12 acceptance criteria satisfied.
- [ ] `npm run build` succeeds.
- [ ] `npx vitest run` 100% pass.
- [ ] `docs/manual_qa_checklist.txt` written with results.
- [ ] ai-work-log final entry added.
- [ ] All commits on `dev`, pushed.

### Out of scope

- Opening the `dev → main` PR itself — Team Lead does this AFTER user approval, not the Implementer.
- Any feature additions — polish only.

### Failure modes

- A §16 step fails — fix minimally; if the fix is non-trivial (>20 LOC or touches a service), escalate via `clarification_request` so Team Lead decides whether to expand scope.
- `npm install` is needed because dependencies changed — that's fine; document.

### Deliverable

- `docs/manual_qa_checklist.txt` with all 13 steps annotated.
- ai-work-log final entry.
- Any polish fixes committed.
- Implementer report: `audits/D009_implementer_report.md`.

### Post-D009 Team Lead actions (NOT the Implementer's responsibility)

After D009 QA PASS:
1. Team Lead surfaces final state to user.
2. Halt for user approval.
3. On approval: open `dev → main` PR via `gh pr create`.
