### What to build

#### 1. ExamService (`client/src/services/ExamService.js`)

Per spec §8:

```js
class ExamService {
  constructor(mockApi, config, logger) { ... }
  async getAllExams()                             // all exams (teacher-side view)
  async getPublishedExams()                       // status === "Published"
  async getExamsByTeacher(teacherId)              // filtered by createdBy
  async getExamById(id)
  async createExam({ title, description, durationMinutes, questions, createdBy })
  async updateExam(id, partial)                   // partial-update; status must use the dedicated method
  async publishExam(id)                           // Draft → Published; reject if not Draft
  async closeExam(id)                             // Published → Closed; reject if not Published
  async deleteExam(id)                            // optional, can be omitted in M1
}
```

State machine **enforced in the service**: `Draft → Published → Closed`. Invalid transitions throw `Error('Invalid status transition: <from> → <to>')`.

- `createExam` sets status to Config.getDefaultExamStatus() (Draft), assigns `id = crypto.randomUUID()`, `createdAt = new Date().toISOString()`.
- Each question created via the service also gets `id`, `examId` set.
- Validate: title non-empty, durationMinutes > 0, questions array (can be empty initially; teacher fills via UI).
